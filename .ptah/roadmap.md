# Roadmap — Qaa El-Hamour

> Generated by saas-workspace-initializer (Stage A).
> Each unchecked item is a Stage B task. Run `/orchestrate <slug>` in a new chat session.

**Project.** An interactive React Three Fiber brand website themed on the viral Egyptian
trend "Qaa El-Hamour" — a scroll-driven camera dive through an underwater scene with
interactive landmarks standing in for portfolio sections. Built as a **config-driven
open-source template** others fork and deploy.

**Stack.** React + R3F + Vite in an Nx monorepo. Static-first hosting with exactly one
serverless seam (functions + Prisma/managed Postgres) serving the public complaints wall.
No auth code of our own. Single-tenant per deployment.

**MVP.** The dive plus two landmarks: the Pineapple (about) and the Complaints Bureau
(contact). The Tiki head and Krusty Krab are deliberately post-MVP.

See `.ptah/scope-decisions.md` for the full discovery record and the asset/IP constraints.

      **Charter.** Render the CC-BY-4.0 attribution for all four models as a visible in-world element — a municipal notice board or credits plaque that fits the art direction instead of fighting it — driven entirely by the `Attribution` records from `asset-manifest`.       **Charter.** Create `libs/world/feature` with the R3F components that make the scene read as deep ocean: exponential fog, a caustics projection on the ocean floor, an instanced bubble/plankton particle system, and the ambient light rig. - [x] dive-camera: Scroll-driven CatmullRom camera path

      **Charter.** Create `libs/dive/{domain,feature}` implementing the dive: a `DivePath` value object over a CatmullRom spline, waypoints per landmark, and a scroll-bound camera controller that eases along the curve. Success: scrolling moves the camera smoothly down the spline, depth state is observable, and the path is defined by data rather than hardcoded coordinates.

- [x] quality-tiers: Adaptive quality and device tiering
      **Outcome.** `QUALITY_PROFILES` (dpr, MSAA, particles, caustics on/off/size, anisotropy, beacon occlusion), capability-based initial tier, hysteresis governor with a wall-clock backstop, `?quality=low|medium|high` override, `trackQualityTier` fired once on settle, `minimumTier` gates model loading. Measured on RTX 3070 headless: 60 fps unthrottled; CPU×4 settles on low ~41 fps. **Known gaps:** CPU×6 only ~21 fps at low (140 draw calls; mesh merging → perf-budget); a single ≥2 s stall can trigger a permanent downgrade (Glm r2 moderate, `quality-governor.ts:138-161` — require repeated stall windows); antialias is fixed at context creation.
      **Charter.** Detect device capability and sustained frame rate, then select a quality tier that gates particle counts, postprocessing, texture resolution, and shadow use — wired to the tier field already present in the asset manifest. A WebGL site that stutters on mid-range Android is unusable for the largely mobile Egyptian audience this trend belongs to. Success: the scene degrades measurably on a throttled device and holds an acceptable frame rate at every tier.
      **Depends on:** world-environment
